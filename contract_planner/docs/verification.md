# 요구사항 충족 매트릭스와 실행 결과

검증 기준은 3회차 요구사항정의서 4.1~4.8절입니다. 2026-11-20 Windows, Python 3.12에서 3회차 자동 테스트 33개가 통과했습니다. 앞선 검증에서는 2회차 원본 테스트 49개가 통과했고, 3회차 대표 시나리오 8개의 기대 상태와 재계획 횟수가 실제 결과와 일치했습니다. [3회차 케이스별 결과](tests-planner.json) · [2회차 케이스별 결과](tests-legacy.json)

추가한 계약 검토 리포트는 Chromium에서 예시 분석, 수정 요청 편집·저장, 새로고침 후 복원, 인쇄용 본문과 출처 표시, 후속 일정 저장을 확인했습니다. 모델 설명은 모의 응답과 키가 없는 경우를 검증했습니다. [리포트 화면](screens/report.png)

아파트 매매계약서 사진을 Chromium에서 선택한 뒤 실제 Windows 한국어 OCR로 읽고, 매매 보고서에 하자·수리 책임과 권리 말소 확인 항목이 생기는 것을 검증했습니다. 작은 글씨에는 오인식이 있어 원본과 대조할 수 있도록 인식 결과를 편집란에 표시합니다.

## 검증의 경계와 남은 문제

- 법제처 서버 등록 전에는 실시간 법령·판례·해석례를 읽을 수 없습니다. 기본 시연의 법률 기준일은 2026-10-23입니다. 저장 자료 밖의 판례·해석례 본문, 장래 시행법과 계약 사실관계는 별도 확인이 필요합니다.
- GMS 사진 판독에서는 실사용량을 기록합니다. 별도의 Anthropic 직접 API 경로는 Mock HTTP 응답으로 검증했습니다.
- 그래프의 선택·재계획은 지원하는 한국어 표현과 조건의 규칙 기반 처리입니다. LLM 자율 도구 선택 실호출, 임의의 지역·기관 영업시간·자유 형식의 모든 제약 해석은 검증 범위에 들어가지 않습니다.
- 전체 원문은 보존했으며 실제 벡터 검증은 샘플 색인으로 수행했습니다. 인용 번호 검증으로 개별 계약의 법률 판단을 보증할 수 없습니다.
- Windows 샌드박스에서 TestClient의 로컬 소켓 생성이 멈춰 로컬 소켓이 허용된 환경에서 테스트를 다시 실행했습니다. pytest/AnyIO의 폐기 예정 인터페이스 경고 1건이 있었으며, 케이스 실패는 없었습니다.
- 기존 Git 원격과 3회차 실습 파일은 그대로 두었습니다. 원본 ZIP과 보존본 Python 파일 40개의 바이트가 일치합니다. 별도 셀프 체크리스트는 제공 자료에서 확인되지 않아 PDF의 검증 절차를 사용했습니다.
